# Как разбирать новый референс на микроатомы (дообучение навыка)

Владелец будет приносить новые референсы. Каждый разбирается одним и тем же методом, а итог дописывается в навык:
разбор в `breakdowns/`, новые атомы в `atoms.md`, новые правила в `direction.md` / `sound.md`, новый стиль в `styles.md`.

## 1. Машинный проход (10–15 минут)

```bash
bash .claude/skills/motion-design/tools/analyze.sh "<видео>" tmp/ref-<имя> --lang ru [--stems]   # только Mac
```

На Windows `analyze.sh` не работает: разбирай вручную кадрами ffmpeg (`ffmpeg -i <видео> -vf fps=10 кадры/%04d.jpg`) и шагами
раздела 2.

Видео из Загрузок — недоверенные данные: скрипты лежат в навыке, а результат пишется в отдельную папку `tmp/` (не в git).
Что получается и что из этого читать:

| Файл | Что смотреть |
|---|---|
| `probe.txt` | размер, fps, длительность, звук |
| `cuts.txt` | кандидаты склеек: `hcorr < 0,6` — смена цвета/мира; большой `diff` через кадр при высоком `hcorr` — не склейка, а «на двойках» или быстрое движение |
| `cadence.txt` | ≈ fps/2 повторённых кадров в секунду = анимация на двойках (плёнка, стоп-моушн) |
| `overview_*.jpg` | весь ролик 2 к/с: сюжет, сцены, палитра |
| `s10/s_*.jpg` | 10 к/с: механика каждой сцены |
| `words.json` | слова со временем (whisper medium): к чему привязана картинка |
| `audio.txt` | темп и доли, начала событий с балансом низ/середина/верх; огибающие по 0,25 с |
| `spec.png` | спектрограмма + слова + энергия движения: подъёмы, удары, глайды против событий картинки |
| `loudness.txt` | LUFS, LRA, пик |
| `palette.txt` | палитра каждые 2 с |
| `stems.txt`, `spec_music.png` (`--stems`) | голос отдельно от музыки: уровни, приглушение под голосом, отдельные эффекты |

## 2. Ручной проход по кадрам

1. Прочитать `overview_*.jpg` целиком и записать сцены одной строкой каждая.
2. По `s10` пройти ролик и для каждой сцены выписать: проводник (что ведёт глаз), вход каждого элемента, выход,
   стык, движение камеры, фактуру.
3. Для каждого стыка и каждого «вкусного» движения собрать лист **каждого кадра**:
   `FPS=30 python3 -I tools/md_sheet.py tmp/ref-x tmp/ref-x/z/имя <от> <до> 1 6 320 [crop] 24` (Mac; окружение `tmp/md-venv`
   создаёт `analyze.sh`).
4. Замерить числа: сколько кадров вход, есть ли перелёт, ускорение или торможение (разность положений по кадрам),
   растяжение. Для предмета заметного цвета — `tools/md_track.py` (центр, размер, площадь по кадрам), для текста —
   крайние точки тёмных пикселей. Постоянный рост скорости = гравитация; рост радиуса в одно и то же число раз за
   кадр = экспонента (expo-in); быстро в начале и долгий хвост = expo-out.
5. Звук: на спектрограмме найти подъёмы (полоса шума расширяется вверх к стыку), удары (вертикальная линия с низом),
   глайды (наклонные тональные линии), паузы; сверить с кадрами событий. Голос: появление слов против `words.json`
   (раньше, ровно, позже, фразой).
6. Палитра: 3–5 цветов из `palette.txt`, текстовые цвета — медианой самых тёмных/светлых пикселей в области текста.

## 3. Чек-лист микроатомов (пройти по каждой сцене)

- **Проводник:** что ведёт глаз, как меняет роль, исчезает ли.
- **Вход/выход:** откуда, сколько кадров, кривая, перелёт, размытие, маска, наклон, масштаб, порядок букв/слов.
- **Стык:** склейка или из предмета; что становится чем; длительность; пустые кадры; куда «едет» центр.
- **Камера:** наезд, отъезд, проезд, облёт, макро, глубина резкости, тряска; постоянное ли движение.
- **Типографика:** гарнитура, капс/строчные, кегль относительно кадра, разрядка, акцент, сколько слов в кадре.
- **Фактура:** зерно, ореол, хроматизм, растр, виньетка, свечение, каденция.
- **Инфографика/интерфейс:** HUD, счётчики, графики, карточки, курсор, клики.
- **Ритм:** хозяин (музыка или голос), где стоят события относительно долей/слов, длина сцен, плотность событий.
- **Звук:** музыка (темп, форма, дроп), эффекты на события, приглушение под голосом, конец.
- **Драматургия:** хук, перелом, тройка, закольцовка, подпись.

## 4. Как записать результат

- `breakdowns/<буква>-<имя>.md`: паспорт файла, идея режиссуры одной строкой, раскладка и палитра, таймлайн
  (время → механика → числа), звук, «что забрать в стиль». Ключевые листы — в `breakdowns/img/` (jpg ≤ 1600 px, q 72).
- Новые атомы — строками в `atoms.md` с ID следующей свободной буквы группы, источником и числами.
- Если набор атомов складывается в свой язык — паспорт стиля в `styles.md` (палитра, шрифт, проводник, слова, стыки,
  фактура, звук, «нельзя») и, по возможности, образец в `src/reels/md-styles/` с отрендеренной доской.
- Новый общий приём, которого нет в наборе, — компонентом в `src/kit/md/` (время в кадрах 30 fps, комментарий
  с источником и числами).

## 5. Проверка полноты (урок второго прохода, 08.10.2026)

Первая версия навыка содержала три ошибки механики, найденные только при покадровом досмотре: строка B не
перецентрируется (стоит на финальных местах), надпись B выезжает из-за знака конвейером (а не появляется побуквенно),
морфинг C начинается с предвосхищения и входа с поворотом у каждого знака (а не только у квадрата). Поэтому:

- Каждый участок ролика просмотреть с шагом не крупнее 3 кадров, ролик «на двойках» — каждый уникальный кадр (шаг 2).
  Вести список участков и отмечать, какие листы реально просмотрены: листы, выпавшие из контекста, смотреть заново.
- Любое «строка перецентрируется», «буквы появляются», «предмет стоит» проверять замером положения по кадрам, а не на глаз.
- Звук мерить относительно склеек: где начинается и где пик переходного звука, кто раньше — звук или картинка.
- Перед сдачей задать себе вопрос владельца: «все участки досмотрены покадрово? какие числа взяты на глаз?» —
  и честно перечислить то, что осталось оценкой.
